## 1. 各成员核心结论

### 🔍 产品评审员

- **核心判断**：这个站的价值不在"把视频搬到网页上"，而在**替代视频教不会的那部分**——装卦与判卷。看视频是输入，装卦是输出，只有输出能被判对错。
- **关键建议**：① 首版只做「装卦台 + 判卷 + 速查」三件套，其他全砍；② 用"可见进度"做留存，**不做任何内容门禁**；③ 玄学内容按"古籍研究工具"定位，不承诺预测效力。

### 🎨 设计顾问

- **核心判断**：中式但不土。视觉母题定为「现代文献学 / 工具书」，不用毛笔字+水墨的廉价古风，改用宣纸底、墨色字、朱砂印记的学术出版物气质。
- **关键建议**：① 卦爻全部用 CSS 绘制（不用字符，避免字体缺字）；② 五行色必须同体系和谐且可区分；③ 错误信号每行只准出现一个红色元素，避免"满屏飘红"。

## 3. 产品方案

### 3.1 定位与分工

> **网站负责"装卦与判卷"，视频负责"讲课与案例"。**

视频不可替代的部分是老师的白话讲解与案例串讲；网站不可替代的部分是**即时反馈的装卦练习**。二者不是搬运关系。

### 3.2 核心学习闭环

```
看单元视频 → 装卦台排一张盘 → 判卷模式自己装一遍 → 被逐爻指出错在哪
   ↑                                                        ↓
   └──────────── 速查卡补漏 ←── 断卦走查走一遍 ←────────────┘
```

### 3.3 信息架构（5 项一级导航）

| 导航      | 内容                          |
| ------- | --------------------------- |
| 学习路径    | 8 张集卡 → 展开 34 个单元，单元详情带视频锚点 |
| 装卦台     | 摇卦 / 手动 / 判卷三模式 + 完整卦盘      |
| 断卦走查    | 6 判定步 + 出结论，每步标章号，可倒查       |
| 案例      | 5 张示例卦，卦盘由引擎复算              |
| 速查 / 手册 | 44 张知识卡 + 8 张对照表；22 章逐章精读   |

### 3.4 MVP 分级

**P0（已实现）**

### 3.5 技术栈与工程结构（v0.2 已迁移）

首版原型是手写原生 HTML/CSS/JS，已验证可行，但不利于长期维护与设计统一。v0.2 整体迁移到成熟框架与组件库：

| 层 | 选型 | 替代了什么手写代码 |
|----|------|------------------|
| 构建 | Vite 6 | — |
| 框架 | Vue 3（`<script setup>`） | 手写 DOM 操作与字符串拼模板 |
| 路由 | Vue Router 4（hash 模式） | 手写 hash 路由 |
| 组件库 | Naive UI 2 | 手写按钮/卡片/输入/下拉/抽屉/进度条/标签 |
| 主题 | Naive UI `themeOverrides` | 每个组件单独写 CSS |
| 历法 | **lunar-javascript** | 手写 JDN 日干支推算 + 近似节气表（±1 天误差） |

**为什么换 lunar-javascript**：它自带精确节气、干支、旬空，直接消掉手写版的近似误差。迁移后核对：2021-10-13 09:19 → 辛丑年 戊戌月 甲午日 己巳时、旬空辰巳，与课件完全一致。

**仍然自研的部分（合理）**：八宫 64 卦归属、纳甲、六亲装配、缺六亲取伏神、六神起法、六冲六合判定。这些是六爻领域逻辑，没有成熟库覆盖，属"领域核心"而非重复造轮子。

## 4. 三条硬约束（写进代码，不只是写在文档里）

### 4.1 视频不转存

`<video>` 直接指向本地 `视频/*.mp4`，无任何转码、切片、上传逻辑。浏览器无法解码 AV1 时降级为"显示文件路径 + 复制"，不做转码兜底。

### 4.2 板书不逐字复制

案例库断语段一律为**本站按课程规则作的示例解读**，页面明确标注"非古籍原文、非板书摘录"。指向老师原话时只给集号，不给逐字句。

### 4.3 内容全可达

全站无锁、无 `not-allowed`、无模糊遮罩、无"先完成 X"。进度只作提示，不换能力。

### 4.4 判卷错因文案规范（实现方必须按此口径）

判卷是本站的核心价值，错因句写坏了，整个功能就废了。规范如下：

**字数口径（必须写明起止边界，否则规则句会被砍空）**

> **24 字 = 从字段名首字到括号末字的全部字符**（含字段名、`「」`、`（）`、`→`），**不含行首 `× ` 与行末回链**。

按此口径，规则句可留 8~10 字，刚好放得下「同我者兄弟」「取本宫同位」这类，不会逼人砍规则。

**版式余量**：错因行可用宽 **536px**（页边距加在栅格容器上、不在列上；1240 档 `1fr` 还会多吃 16px 余量）。24 字需求约 428px，余 108px，字体回退也不会折行。**不要按 480px 算。**

**两条防回退自查（重写时最容易砍掉的东西）**

1. **规则句必须保留**——只剩答案、没有依据的错因句，价值为零。
2. **引号值不得截断**——伏神类字段的值含伏位（如 `妻财寅木 伏二爻下`），砍成 `妻财寅木` 等于没答。

**实现方式**：`white-space: nowrap` 是防止折行的兜底，**不靠 CSS 截断**——超长必须在文案侧收到 24 字以内。当前已实现的六亲/世应两条实测各 22~24 字，符合口径。

### 4.5 判卷：部分判 + 难度阶梯（这一条决定留存）

**问题**：如果 12 格全填才能判，用户必须坐满 5 分钟，会直接废掉「每日一卦 5 分钟」这个唯一可行的留存机制。

**规则**

- **部分判**：勾了几格就判几格，不要求填完，不写"未完成"。汇总固定三件事：`已判 X/Y 格 · 全对 Z 格`。
- **缺失 ≠ 未作答**：该填没填（结构上必需）算缺失型，带 `×`；用户主动跳过的算未作答，只显示灰色「未作答」，**不飘红**。
- **难度自动升档**，不让用户选（选难度是决策负担，零基础必选错档）：
  | 档  | 触发条件        | 判定字段           | 预填       | 格数 |
  | -- | ----------- | -------------- | -------- | -- |
  | 入门 | 默认          | 卦名 + 六亲 + 世应   | 地支、五行、卦宫 | 13 |
  | 进阶 | 判卷满 10 次    | + 纳甲 + 五行 + 六神 | 卦宫       | 31 |
  | 完整 | 累计全对 ≥ 60 格 | 同上             | 无        | 31 |
- **入门档必须预填纳甲**：六亲是靠"爻地支五行 vs 卦宫五行"推出来的，把地支藏起来等于第一题就做不出。同理预填卦宫名（含宫五行），否则世应也无从判断。

**预填泄漏自检判据**（与四条语气判据并列，新增字段时必须过这一条）：

> **这一格能不能被旁边的预填值反推出答案？能，预填就得撤。**

扫三档：

- 入门：预填地支可反推五行，但**入门不判五行** → 不产生"假会" ✓
- 进阶：**五行与纳甲都是可填格**，不是预填值 → 无泄漏 ✓（这一条正是本方案与设计稿 7 格版的唯一分歧点，已按 8 格口径实现）
- 完整：撤掉卦宫预填，世应要自己从"卦宫 → 第几世 → 世位"跳 ✓

**为什么这条必须写死**：预填泄漏只对"不判的格"无害；一旦该格参与判卷，泄漏就变成**虚假的正确感**——用户会自信地填错，比直接不会做更难发现。五行预填「金」时，纳甲只剩申酉二选一，50% 靠猜，而用户只会觉得自己学会了纳甲。

**为什么这是 P0 而不是 P1**：没有部分判，判卷只有"全填才能用"和"不能用"两种状态，中间没有台阶，零基础用户第一次就会撞墙。

### 4.6 措辞规范：「补你」判据

禁用**删动词**（去掉、删掉、砍掉），一律改「补你」。判据只有一条：

> **补完这句，用户此刻就多了一个"能用"的东西 → 用「补你」。**  
> 只是把话说完整、不增加可用性 → 用「注明」。

例：

- 「站内不支持逐字稿，**补你**集号 + 一句口述要点」✓（多了一个可跳转的锚点）
- 「标题里去掉'暂无原文'，**注明**断语为示例解读」✓（只是措辞，不增加可用性）

### 4.7 视觉红线：五行退出颜色系统

原设计用五行色标（木青/火赤/土黄/金白/水玄）给六亲着色。实测在判卷页撞出一条硬伤：**火赤 `#B4432C` 与错误红 `#A6331F` 几乎同色，同一屏出现两种红**，用户分不清"这是五行火"还是"这里错了"。而且纯颜色编码对色盲用户不可读。

**处理（已改，无例外）**：五行一律写成**汉字单字**「木火土金水」——

- 判卷预填：`--ink-2` + 600 字重，无底色
- 卦盘六亲：六亲词用墨色，五行单字用 `--ink-3`，无底色

**色相分工（结构约束，不是调色建议）**

> **填充色归五行，状态色归边框。**

本版干脆不启用五行填充，所以"第四种颜色"问题从结构上就不存在。将来若要恢复五行填充，状态一律走 2px 边框（`--bad` / `--good`），不得用底色——这样两种语义在物理上不可能撞。

**为什么不靠"调色值"解决**：把火色调开 15° 只是把问题推给下一个人。红只留给"错了"，五行作为给定条件不需要抢红。

### 4.8 判卷颗粒度（已对齐，无分歧）

`DESIGN.md` 与原型现已统一为 **13 / 31 格**（每爻一答，6 爻 × 字段 + 卦名）：

| 档  | 判定字段           | 预填       | 格数 |
| -- | -------------- | -------- | -- |
| 入门 | 卦名 + 六亲 + 世应   | 地支、五行、卦宫 | 13 |
| 进阶 | + 纳甲 + 五行 + 六神 | 卦宫       | 31 |
| 完整 | 同上             | 无        | 31 |

设计稿早期的 3/8 格版（每卦一答）已废弃：它只能说"纳甲错了"，说不到"第三爻的纳甲错了"——而后者才是判卷的全部价值。
